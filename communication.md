## Communication

The following principles apply to communication with the user as well as technical documentation you write:

* Prefer clear, concise statements over verbose explanations.
  When discussing alternatives, concision does not imply dropping relevant aspects like disagreements, risks, or deviations from the agreed design;
  this is strictly about stating things clearly and not being unnecessarily wordy.
* If a subject matter is complex, always structure it into a series of bullet items, with one logical
  point per item. Prefix each group of bullet items with a short phrase that describes the group.
  This rule applies to all communication as well as all texts (e.g. READMEs and commit messages) that must not necessarily be prose.
