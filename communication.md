## Communication

The following principles apply to communication with the user as well as to READMEs and all other documentation you write:

* Prefer clear, concise statements over verbose explanations.
  When discussion alternatives, concision does imply dropping relevant aspects like disagreements, risks, or deviations from the agreed design;
  this is strictly about not being unnecessarily wordy and stating things clearly.
* If a subject matter is complex, always structure it into a series of bullet items, with one logical
  point per item. Prefix each group of bullet items with a short phrase that describes the group.
