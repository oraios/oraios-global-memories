## Commits

Commit messages:
* The subject line must cover the *entire* change; make it suitably abstract if necessary
* Explain the concrete motivation and resulting behavior
* Organize the explanation by semantic topic, using as many sections as needed with meaningful headings; do not impose a fixed template.
* Write section headings as plain text ending in a colon (for example, `Validation:`), with the content on the immediately following line.
* Use a single sentence for one logical statement. Use concise bullet items for multiple distinct points, one point per item; never combine several points into a prose paragraph.
* Keep semantically distinct information in separate groups: motivation or validation aspects must not be mixed into a list of changes.
* Wrap all lines at ~100 characters.
* Write the message to a file and commit with `-F`; do not pass long text via `-m`.
